Home Credit Installment — Implementation Approach

Pick the data model that best fits how you want to track HC payments

A

Extend the Transactions Table Recommended

Add HC-specific columns to the existing transactions table — same pattern as how check_bank_name, ewallet_reference etc. work today.

New columns: hc_downpayment · hc_terms · hc_amount · hc_status (pending/received) · hc_received_at

Pros

  • Follows existing pattern exactly
  • No extra joins on tracking page
  • Simpler migration

Cons

  • Transactions table gets wider
B

Separate installment_plans Table

Create a new table linked to the transaction via FK. Cleaner schema, more flexible for future features (e.g., partial payouts, multiple HC references).

New table: installment_plans — transaction_id · downpayment · terms · hc_amount · status · received_at

Pros

  • Cleaner, more normalized
  • Easier to extend later

Cons

  • Extra join on every query
  • More code to write
  • Overkill for a single lump-sum payout

Either way — the tracking page and POS flow look the same
